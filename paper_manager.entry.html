paper_manager.entry package#

論文エントリと論文リストを管理するモジュール。

このモジュールは、学術論文の情報を管理するためのクラスを提供します。

主なクラス:

Entry: 個々の論文エントリを表す辞書風のクラス PaperList: 複数の論文エントリを管理する辞書風のクラス

論文リストのファイルの読み込みと退避:
load_paper_list: ファイルを読み込み、状態 (PaperListStatus: 正常・

ファイルなし・壊れている) とともに返す (PaperListLoad)

backup_broken_paper_list: 壊れたファイルを日時入りの別名へ複製する

PDF の警告の記録:
KEY_SHOWN_PDF_WARNINGS: 画面に出した PDF の移行・アクセスの警告を記録する

session state のキー (config_page が描画の冒頭で消す)

引用キー:
sanitize_citation_key: BibTeX の引用キーとして読めない文字 (空白・,・

{・}) を除く

unique_citation_keys: 整えたうえで、大文字小文字を区別せずに重複しない

引用キーの並びにする

例:
>>> from paper_manager.entry import Entry, PaperList
>>> entry = Entry({
...     "ENTRYTYPE": "article",
...     "title": "Example Paper",
...     "author": "John Doe",
...     "year": "2024"
... })
>>> paper_list = PaperList({"key1": entry})
>>> len(paper_list)
1
class paper_manager.entry.Entry(_Entry__mapping: Mapping[str | Literal['ENTRYTYPE', 'ID'], str])#

Bases: MutableMapping

論文エントリを表す辞書風のクラス。

このクラスは、学術論文の情報（著者、タイトル、ジャーナル、DOIなど）を 管理するための辞書風のインターフェースを提供します。

特徴:

  • 辞書のようにアクセス可能（entry["title"]）

  • 値の前後の空白を自動的に削除

  • 一意なキーの生成機能

  • 複数のPDFファイルをサポート（各エントリごとに専用ディレクトリ）

PDFファイルの管理:

各エントリは、pdf_dir_name`プロパティで生成されるディレクトリ名の フォルダにPDFファイルを保存します。複数のPDFファイルをサポートしており、 各ファイルは`00.pdf, 01.pdf, `02.pdf`のように連番で命名されます。

旧バージョンとの互換性:

  • `pdf_filename`プロパティは非推奨（deprecated）です

  • 旧形式のPDFファイルは自動的に新しい形式に移行されます

属性:
pdf_dir_name: PDFファイルを保存するディレクトリ名を生成するプロパティ

（形式: '<year> - <first_author> - <title>'）

メソッド:

get_key: 既存のキーと重複しない一意なキーを生成 get_pdf_dir: PDFファイルを保存するディレクトリのパスを取得 get_pdf_files: このエントリに関連するPDFファイルのリストを取得 has_pdf: PDFファイルが存在するかどうかを確認 get_pdf_count: 関連するPDFファイルの数を取得

例:
>>> entry = Entry({
...     "ENTRYTYPE": "article",
...     "title": "Example Paper",
...     "author": "John Doe",
...     "year": "2024"
... })
>>> entry["title"]
'Example Paper'
>>> entry.pdf_dir_name
'2024 - John Doe - Example Paper'
>>> pdf_files = entry.get_pdf_files()
>>> len(pdf_files)
2  # 複数のPDFファイルが存在する場合
get_key(keys: Collection[str]) → str#

Generate a unique key using the ‘author’ and ‘year’ fields.

Parameters:

Returns:

A unique key based on the first author’s name and the year, <first_author><year>_<n>. Whitespace, ,, { and } are removed (see sanitize_citation_key()) because BibTeX cannot read them in a citation key. The duplicate check against keys is case-sensitive.

get_pdf_dir(base_dir: Path | None = None) → Path#

Get the directory path for storing PDF files.

このエントリ専用のPDFディレクトリのパスを返します。 複数のPDFファイルは、このディレクトリ内に`00.pdf`, 01.pdf`のように 連番で保存されます。パスは、ファイル操作用に変換した PDF ルート (``to_fs_path`。Windows では拡張長のパス) から作るので、パス全体の 長さにかかわらず、そのままファイル操作に使えます。画面とログには to_display_path で戻したパスを出します。

Parameters:

base_dir (Union[Path, None], optional) – Base directory for PDF storage. If None, uses DIRPATH_PDF.

Returns:

to_fs_path(base_dir or DIRPATH_PDF) / pdf_dir_name.

Return type:

Path

get_pdf_files(base_dir: Path | None = None) → list[Path]#

Get a list of PDF files associated with this entry.

このエントリに関連するすべてのPDFファイルのリストを返します。 ファイルは`00.pdf`, 01.pdf, `02.pdf`のように連番で命名され、 ソートされた順序で返されます。

旧バージョンとの互換性:

一覧を作る前に、次の順で旧形式から移行します。どの移行も 既存のファイルを上書きしません。

  1. 現在の名前のフォルダがなく、修正前の規則の名前 (legacy_pdf_dir_name) のフォルダがあれば、現在の名前へ 移す。移す先が既にあれば移さない

  2. 旧形式の単一 PDF (base_dir/pdf_filename) があれば、 フォルダの有無にかかわらず、フォルダの空いている番号へ移す

  3. フォルダ内の旧命名規則のファイル名を NN.pdf に変える

移行に失敗したとき、または移す先が既にあるため移さなかった ときは、ログと画面の警告 (表示用のパス) の両方に出します (同じ警告は 1 回の描画の中で 1 回だけ)。

Parameters:

base_dir (Union[Path, None], optional) – Base directory for PDF storage. If None, uses DIRPATH_PDF.

Returns:

The PDF files in the folder sorted by name, followed by the legacy single PDF when it could not be moved into the folder (so that it stays visible). Paths are under the converted PDF root (see get_pdf_dir). Empty list if no PDFs exist. It never raises.

Return type:

list[Path]

property legacy_pdf_dir_name: str | None#

Return the folder name built with the rule before the KB7 fix.

後方互換のための修正前の規則の名前。KB7 の範囲で修正後の名前 (pdf_dir_name) と異なり、いずれかの OS でフォルダを作れた長さ (255 文字以内) のときだけ値を持つ。その名前のフォルダは、PDF の 一覧の取得時に現在の名前へ移す (KB7 の範囲の移行と孤立判定だけで 使う)。

Returns:

The pre-fix folder name when it differs from pdf_dir_name and has at most 255 characters, otherwise None. It never raises.

Return type:

Optional[str]

property pdf_dir_name: str#

Generate a sanitized directory name for the entry’s PDF files.

The directory name format is ‘<year> - <first_author> - <title>’. If the resulting name is too long, the title will be truncated to fit within the maximum directory name length. If it is still too long, ‘<year> - <first_author>’ is used, and then the year cut to the maximum length. A name that would be empty is replaced with Unknown. The name does not depend on where the PDF directory is located.

Returns:

A sanitized, non-empty directory name for the entry. It has at most MAX_DIRNAME_LENGTH characters and does not end with . or a space. A non-empty name that fits with the rule used before the KB7 fix is returned unchanged, so existing folders keep their names.

Return type:

str

property pdf_filename: str#

Deprecated since version Use: pdf_dir_name and get_pdf_files() for multiple PDF support. This property is kept for backward compatibility and will be removed in a future version.

Generate a sanitized filename for the entry’s PDF file.

Deprecated since version Use: pdf_dir_name and get_pdf_files() for multiple PDF support. This property is kept for backward compatibility and will be removed in a future version.

The filename format is ‘<year> - <first_author> - <title>.pdf’. A missing title falls back to Unknown (as in pdf_dir_name) so that entries without a title do not raise. Otherwise the name is kept unchanged to find legacy single PDF files.

str

A sanitized filename for the entry.

class paper_manager.entry.PaperListStatus(*values)#

Bases: str, Enum

State of the paper list file, judged from its contents.

OK#

The file is a JSON object of entries (key -> JSON object of fields) whose field values are all strings.

MISSING#

There is no file at the path. A directory at the path also counts as no file (as before this state was introduced).

BROKEN#

The file cannot be decoded as UTF-8, cannot be parsed as JSON, or is not a JSON object of entries whose field values are strings (the top level is not an object, including null; an entry is not an object; or a field value is not a string).

BROKEN = 'broken'#
MISSING = 'missing'#
OK = 'ok'#

paper_manager.entry.sanitize_citation_key(key: str) → str#

Remove the characters that BibTeX cannot read from a citation key.

pybtex reads the citation key of a brace-delimited entry up to the next whitespace, , or }. Whitespace (every character for which str.isspace() is true), ,, { and } are removed ({ is removed as well so that braces stay balanced). Every other character (., -, ', \, non-ASCII characters and so on) is kept, so a key that is readable today does not change.

Parameters:

key (str) – A citation key.

Returns:

The key without the characters above, or Unknown when nothing is left. Applying the function again returns the same key.

Return type:

str

paper_manager.entry.unique_citation_keys(keys: Sequence[str]) → list[str]#

Return citation keys that are unique ignoring case.

pybtex treats citation keys case-insensitively and raises an exception when two keys differ only in case. Each key is cleaned with sanitize_citation_key(). A key that duplicates an earlier one (ignoring case) gets the suffix _<n> (the smallest n >= 1 that no other key, earlier or later, uses). The first occurrence of a key is never changed.

Parameters:

keys (Sequence[str]) – Citation keys, for example the IDs of the entries to export.

Returns:

Keys in the same length and order as keys, with no duplicates ignoring case. Without duplicates, each element is sanitize_citation_key applied to the input element.

Return type:

list[str]
